1 · Engine, lifecycle and launcher

engine/core · E-04, E-06, E-13 · round 8
function + CMakelauncher main()Locked

The engine ships one generic main(). Games write no main() and no loop; CMake builds the launcher once per executable name.

Pattern inversion of controlDecision E-06
// engine/launcher/main.cpp  (engine code, written once)
int main(int argc, char** argv) {
    return engine::Engine(
        engine::EngineConfig::load(ENGINE_DEFAULT_CONFIG, argc, argv)).run();
}

# a game's CMakeLists.txt
engine_add_launcher(r-type_client CONFIG client.yaml)
engine_add_launcher(r-type_server CONFIG server.yaml)
enum classRoleLocked

The role of the process. Decides which plugins load and which systems a game registers.

enum class Role { Client, Server, Editor };
structEngineConfigLocked

Read at startup from a file, overridden by command-line options. Plugin names resolve to files: platform: sfml loads plugins/libplatform_sfml.so.

struct EngineConfig {
    Role role;
    std::string game;        // "rtype"
    std::string platform;    // "sfml" | "raylib"   (client only)
    std::string audio;       // "miniaudio"          (client only)
    std::string network;     // "asio"
    double tickRate = 60.0;  // simulation steps per second
    std::filesystem::path root;
    static EngineConfig load(const std::filesystem::path& file, int argc, char** argv);
};
classEngineLocked

The composition root: owns every subsystem, runs the lifecycle, loads plugins and the game. The game never sees it. Member order is an architecture decision: members are destroyed bottom to top, so scenes die before the game module is unloaded and the logger outlives everyone who writes to it.

Patterns composition root, Template Method (run()), RAIIDecisions E-04, E-06
class Engine {
public:
    explicit Engine(EngineConfig config);
    int  run();                    // boot → load → loop → shutdown, returns exit code
    void requestQuit() noexcept;   // thread-safe: signal, window close, console

private:
    void boot();                   // logger, plugins of the role, game module, registerTypes
    void load();                   // registerSystems, first scene, assets, onStart
    void loop();                   // THE game loop (fixed step + interpolation)
    void shutdown();               // onShutdown, clear scenes, then RAII does the rest

    EngineConfig     config_;
    Logger           logger_;      // destroyed after the modules (they log on unload)
    ModuleManager    modules_;     // owns the .so/.dll: destroyed last among subsystems
    TypeRegistry     types_;
    EventBus         events_;
    AssetManager     assets_;
    InputMap         input_;
    Scheduler        scheduler_;   // holds game systems: destroyed before modules_
    SceneManager     scenes_;      // holds game components: destroyed before modules_
    RenderQueue      renderQueue_;
    Clock            clock_;
    std::atomic_bool running_{false};
};
classContextLocked

The only door from game code into the engine. A non-owning view passed to every system and to the game hooks. References, never pointers: a missing service is a Null Object, so no call can hit nullptr. Used on the loop thread only.

Patterns Facade, Dependency InjectionNetwork access added in the network block
class Context {
public:
    Registry&          world();          // registry of the ACTIVE scene (changes on switch)
    Commands&          commands();       // deferred spawn / destroy / add / remove (ECS-4)
    SceneManager&      scenes();         // switchTo("scenes/level1.yaml")
    EventBus&          events();
    const ActionState& input() const;    // actions (MoveUp, Fire), never keys
    AssetManager&      assets();
    RenderQueue&       render();         // E-07
    IAudio&            audio();          // NullAudio on the server
    const Time&        time() const;
    Logger&            log();
    Role               role() const;
    void               requestQuit();    // a request; the frame finishes cleanly

private:
    friend class Engine;                 // only the engine builds a Context
    explicit Context(Engine& e);
    Engine* engine_;
};

Read-only timing given to systems through ctx.time().

struct Time {

2 · Modules and plugins

engine/modules · E-02, E-05, E-06, E-10
interfaceIGameModuleLocked

The contract every game implements. Three questions the engine asks at startup, plus two notifications. Replaces the earlier registerServer / registerClient pair, so a new role (Editor) never changes the interface.

Patterns Template Method hooks, Abstract Factory entry pointNaming interfaces start with I
class IGameModule {
public:
    virtual ~IGameModule() = default;
    virtual void registerTypes(TypeRegistry& types) = 0;            // "which components did you invent?"
    virtual void registerSystems(Role role, Scheduler& s) = 0;      // "what logic runs, and when?"
    virtual std::string_view firstScene() const = 0;                // "where do I start?"
    virtual void onStart(Context& ctx) {}                           // once, before the loop
    virtual void onShutdown(Context& ctx) {}                        // once, world still alive
};

extern "C" EXPORT IGameModule* create_game();       // never throws: returns nullptr on failure
extern "C" EXPORT void destroy_game(IGameModule*);  // freed by the module that allocated it
macro + CMakeENGINE_GAME_MODULE · engine_add_game_moduleLocked

What a game author writes to plug a game in. The macro generates the two extern "C" functions with the Windows export and the mandatory try/catch, so no game writes that boilerplate by hand. The CMake function builds the module as a shared library or statically, following ENGINE_DYNAMIC_MODULES (E-10).

Precedent Unreal IMPLEMENT_PRIMARY_GAME_MODULE
// src/PongModule.cpp
class PongModule : public engine::IGameModule { /* registerTypes, registerSystems, firstScene */ };
ENGINE_GAME_MODULE(PongModule)      // → create_game() / destroy_game()

# CMakeLists.txt
find_package(rtype_engine REQUIRED)
engine_add_game_module(pong_game src/PongModule.cpp src/Systems.cpp)
engine_add_launcher(pong CONFIG pong.yaml)

classModuleManagerLocked

Loads plugins by category and name, loads the game module, keeps libraries open until the very end. With ENGINE_DYNAMIC_MODULES=OFF it resolves the same names from a static table instead (E-10).

class ModuleManager {
public:
    template <class I>
    I& load(std::string_view category, std::string_view name);  // "platform", "sfml"

};
null objectsNullPlatform · NullRenderer · NullAudioLocked

Implement the interfaces and do nothing. Used on the server, in CI tests, and as a fallback when no audio device exists. Never used to hide a real error: a client whose rendering plugin fails stops with a message. Each one is announced once in the logs.

Pattern Null Object
class NullAudio final : public IAudio {
public:
    void play(SoundHandle, float) override {}
    void playMusic(MusicHandle) override {}
    void stopMusic() override {}
};

class templateSparseSet<T>Locked

One per component type. Paged sparse array maps entity to dense position; dense arrays stay packed. O(1) add and remove by swap-and-pop. Never keep a pointer to a component.

Decision ECS-2Pattern Data Locality
template <class T>
class SparseSet final : public IStorage {
    std::vector<std::unique_ptr<uint32_t[]>> sparse_;  // pages of 4096
    std::vector<Entity> dense_;
    std::vector<T>      data_;
public:
    T&   emplace(Entity, T value);
    T&   get(Entity);
    T*   tryGet(Entity);
    void remove(Entity) override;   // swap with last, pop
};

classScheduler · Stage · SystemLocked

The timetable of systems. Named systems in fixed stages, ordered by after/before constraints, timed for the profiler; a throwing system is disabled on the server (ADR 0028).

Patterns Game Loop, Update MethodBlock 5
enum class Stage { FixedUpdate, LateUpdate, Render };
using SystemFn = std::move_only_function<void(Context&)>;

class Scheduler {
public:
    SystemBuilder add(Stage, std::string name, SystemFn);  // .after() .before() .roles() .critical()
    Result<void> build();                // engine only: topological sort, cycles are boot errors
    void run(Stage, Context&);           // engine only: times systems, applies the failure policy
    void setEnabled(std::string_view name, bool);
    std::span<const SystemStats> stats() const;
};
classEventBusLocked

Typed events, queued by default and delivered after each fixed step and after LateUpdate. Subscriptions are RAII: destroying one unsubscribes (ADR 0029).

interfaceINetworkLocked

Engine side of networking (E-13): transport, connections, timeouts and crash notification, packet validation, network thread, replication. Designed in the network block; the protocol itself has its own part.
