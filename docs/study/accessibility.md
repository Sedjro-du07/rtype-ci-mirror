# Accessibility

The subject asks for answers to physical and motor, audio and visual, and mental and cognitive
needs. The engine provides the means; the game turns them on (checklist for the game:
[guide 25](../engine/guide/25-accessibility.md)).

## What exists, per need

| Need | Engine feature | Status |
|---|---|---|
| **Motor**: cannot use some keys | every action rebindable, conflicts detected, saved to `input.yaml` | done (ENG-29) |
| **Motor**: one hand | an alternate one-handed binding set | done (ENG-29) |
| **Motor**: cannot hold a key | `holdToToggle` per action | done (ENG-29) |
| **Motor**: cannot tap fast | `autoRepeat` (auto-fire) per action | done (ENG-29) |
| **Motor**: gamepad only | gamepad buttons, sticks with deadzone, d-pad | done (ENG-29, ENG-31) |
| **Visual**: colour blindness | colour filters (`r_color_filter`) | to do (ENG-33) |
| **Visual**: small text | UI scale (`r_ui_scale`) | to do (ENG-33) |
| **Visual**: any window size | letterboxed virtual resolution, aspect kept | done (ENG-31) |
| **Audio**: deaf or hard of hearing | captions: a sound played with a caption publishes a `Caption` event for the HUD | done (ENG-34) |
| **Audio**: sensitive to some sounds | four volume buses: master, music, effects, interface | done (ENG-34, ENG-35) |
| **Audio**: where a sound comes from | positional panning around the listener | done (ENG-35) |
| **Cognitive**: errors | messages in plain words, with file and line for data errors | done |
| **Cognitive**: pace | fixed tick rate; pausing and difficulty through game state and CVars | partly (CVars: ENG-45) |

## Choices and alternatives

| Choice | Alternative | Why |
|---|---|---|
| captions as an **event** generated by the engine | each backend draws captions | works with every audio and platform plugin; the game decides how they look |
| rebinding in `InputMap`, not in the platform plugin | rely on SDL's gamepad remapping | same rebinding on every backend; keyboard and gamepad in one place |
| colour **filters** applied to the whole frame | per-sprite palettes | no change to assets; the game must still not rely on colour alone |
| actions, not keys, everywhere in game code | read keys directly | rebinding becomes free for the game |

## What the game must still do

Give the four players different shapes, not only colours; caption every gameplay sound; expose the
options in a menu; allow pause in solo play. Menus navigable without a mouse need the UI block,
which is not in the engine yet.
